# Протокол Hermes Go Mobile (версия 1)

Транспорт — WebSocket, каждое сообщение — один JSON-кадр в UTF-8. Точка входа по умолчанию:
`ws://<хост>:8787/ws`, при работе через HTTPS — `wss://<домен>/mobile-ws` (см. `adapter-install.md`).

Реализация протокола на стороне адаптера — `adapter/hermes_mobile/protocol.py`; тесты —
`tests/test_protocol.py`, `tests/test_capabilities.py`. Клиентская реализация —
`mobile/src/api/hermesClient.ts`.

## Общие правила

* Кадр — JSON-объект. Поле `t` (тип) обязательно, регистр не важен.
* `v` — версия протокола; сервер объявляет её в кадре `ready`. Номер версии не меняется:
  все описанные ниже кадры и поля — обратно совместимые дополнения.
* `id` — идентификатор, который задаёт клиент. Для `text`/`audio`/`media` он **обязателен для
  идемпотентности**: повтор с тем же `id` игнорируется (защита от повторной отправки после
  обрыва сети).
* Неизвестные типы кадров и неизвестные поля **игнорируются** — не разрывайте соединение.
* Пределы: кадр ≤ 16 МБ, текст ≤ 12 000 символов, аудио ≤ 8 МБ, один медиафайл ≤ 8 МБ
  (большие — кусками, см. раздел «Медиа»).

## Рукопожатие

1. Клиент подключается к `ws(s)://…/ws` (токен можно передать параметром `?token=…`).
2. Первым кадром клиент обязан отправить `hello`:

```json
{"t":"hello","token":"<токен>","device":{"id":"tel-1","name":"Телефон Евгения","platform":"android","app_version":"1.0.0"},"user":{"id":"u-1","name":"Евгений"}}
```

3. Сервер отвечает `ready` и в `capabilities` объявляет, что он умеет:

```json
{"t":"ready","v":1,"session":"mobile:tel-1","device":{"id":"tel-1","name":"Телефон Евгения"},"avatar_url":"https://hermes-go.com/avatar/index.html?v=2","capabilities":{"text":true,"voice":true,"typing":true,"avatar_states":["idle","thinking","speaking"],"media_in":["image","video","document","audio"],"media_out":["image","voice","video","document","animation"],"prompts":["exec_approval","slash_confirm","clarify"],"edit":true,"max_media_bytes":8388608,"max_text_chars":12000}}
```

Поля `capabilities`:

| Поле | Значение | Смысл |
|---|---|---|
| `text` / `voice` / `typing` | `true` | базовые возможности |
| `avatar_states` | список | состояния аватара (`idle`/`thinking`/`speaking`) |
| `media_in` | список | какие типы медиа принимает сервер от приложения (`image`, `video`, `document`, `audio`) |
| `media_out` | список | какие типы медиа сервер может прислать приложению (`image`, `voice`, `video`, `document`, `animation`) |
| `prompts` | список | типы карточек-вопросов: `exec_approval`, `slash_confirm`, `clarify` |
| `edit` | `true` | сервер умеет править ранее отправленное `message` по `id` (потоковая выдача) |
| `max_media_bytes` | число | потолок одного медиафайла (8 388 608 = 8 МБ) |
| `max_text_chars` | число | потолок текста сообщения (12 000) |

При неверном токене или устройстве вне белого списка сервер отправляет `error` с
`fatal: true` и закрывает соединение кодом **1008**.

`session` — идентификатор сессии в Hermes (`mobile:<device.id>`); он же адрес доставки для
`hermes send --to mobile:<device.id>`. В `hermes send`/`cron` можно указать и просто
`<device.id>` без префикса — адаптер добавит его сам (см. раздел «Адресация устройств»).

## Клиент → сервер

| Кадр | Поля | Смысл |
|---|---|---|
| `hello` | `token`, `device{id,name,platform,app_version}`, `user{id,name}` | рукопожатие |
| `text` | `id`, `text` | текстовое сообщение агенту |
| `audio` | `id`, `format` (`wav`/`ogg`), `data` (base64), `text` (необязательный распознанный текст) | голосовое сообщение |
| `media` | `id`, `kind` (`image`/`video`/`document`/`audio`), `mime`, `filename`?, `caption`?, `data` (base64), `part`?, `parts`? | медиа от приложения агенту (фото, файл, видео, аудио) |
| `prompt` | `prompt_id`, `option_id`, `text`? | ответ на карточку-вопрос (кнопка) |
| `typing` | — | пользователь печатает (сервер может учитывать) |
| `ping` | `ts` | проверка связи |
| `ack` | `id` | приложение показало/проиграло сообщение |
| `deliver` | `id`, `target`, `text` | служебная доставка (cron/`hermes send`) |

## Сервер → клиент

| Кадр | Поля | Смысл |
|---|---|---|
| `ready` | `v`, `session`, `device`, `avatar_url`, `capabilities` | подключение принято |
| `typing` | `stop`? | агент работает: показать индикатор; `stop: true` — гасить индикатор |
| `message` | `id`, `text`, `chunk{index,total}`, `final`, `edit`? | ответ агента (длинный текст — несколькими кадрами, один и тот же `id`); `edit: true` — правка ранее отправленного сообщения |
| `prompt` | `id`, `kind`, `text`, `options[{id,label,style}]`, `session`, `timeout_seconds` | карточка-вопрос с кнопками |
| `prompt_done` | `id`, `option_id`?, `expired`? | карточка закрыта: выбран вариант, либо истёк таймаут (`expired: true`) |
| `media` | `id`, `kind`, `mime`, `filename`, `caption`?, `part`, `parts`, `final`, `size`, `data` (base64, кусками), `url`?, `reply_to`? | медиа от агента приложению |
| `avatar` | `state` (`idle`/`thinking`/`speaking`) | состояние аватара |
| `error` | `code`, `message`, `fatal` | ошибка |
| `pong` | `ts` | ответ на `ping` |

Порядок кадров при типичном ходе: `avatar:thinking` (и `typing`) → `message` (1..N частей)
→ `avatar:speaking` → через паузу `avatar:idle`. Если в конце приходит `typing` с
`stop: true` — индикатор гасится немедленно, не дожидаясь таймаута аватара.

## Карточки-вопросы

Карточка — это сообщение `prompt` с кнопками, на которое приложение отвечает одним кадром
`prompt` (клиент → сервер). Ответ **не** становится обычным сообщением в чате: адаптер
резолвит его штатными механизмами Hermes (одобрение команды, подтверждение слэш-команды,
уточнение).

### Кадр `prompt` (сервер → клиент)

```json
{"t":"prompt","id":"5f6a…","kind":"exec_approval","text":"Опасная команда rm -rf …","options":[{"id":"once","label":"✅ Одобрить один раз","style":"primary"},{"id":"deny","label":"❌ Отклонить","style":"danger"}],"session":"mobile:tel-1","timeout_seconds":300}
```

* `id` — идентификатор карточки (`prompt_id`); его нужно вернуть в ответе.
* `kind` — тип: `exec_approval`, `slash_confirm` или `clarify`.
* `text` — заголовок/вопрос.
* `options` — кнопки: `id` (что отправить), `label` (что показать), `style` (подсказка для
  оформления: `primary`, `danger` или пусто).
* `session` — сессия Hermes, которой адресован ответ.
* `timeout_seconds` — сколько карточка живёт (по умолчанию 300 с).

### Кадр `prompt` (клиент → сервер)

```json
{"t":"prompt","prompt_id":"5f6a…","option_id":"once"}
```

* `prompt_id` — `id` из карточки.
* `option_id` — идентификатор выбранного варианта (значения ниже).
* `text` — необязательный «свой ответ» (используется при `option_id: "other"` в `clarify`;
  допустим и вместо `option_id`, если пользователь ввёл текст руками).

### Типы карточек и допустимые ответы

| `kind` | Варианты `option_id` | Неизвестное значение превращается в |
|---|---|---|
| `exec_approval` | `once`, `session`, `always`, `deny` | `deny` |
| `slash_confirm` | `once`, `always`, `cancel` | `cancel` |
| `clarify` | `c0`, `c1`, … (по порядку вариантов), `other` | запрос текста (`other`) |

Для `clarify` вариант `cN` означает «выбран N-й предложенный вариант» (нумерация с нуля),
а `other` — «пользователь введёт свой ответ»: в этом случае приложение **должно** передать
`text`, иначе сервер переведёт вопрос в режим ожидания текста.

### Правила безопасности

* **Ответ валидируется на стороне адаптера.** Клиент не может «подделать» вариант: любое
  значение вне таблицы выше заменяется на безопасное (`deny` для одобрения опасной команды,
  `cancel` для слэш-команды). Полагаться на клиент нельзя — сервер не сделает «ещё что-то»
  из выдуманного `option_id`.
* Карточка живёт `timeout_seconds` (по умолчанию 300 с). По истечении приходит
  `prompt_done` с `expired: true`, а ответ на просроченную карточку игнорируется и
  подтверждается тем же `prompt_done{expired:true}`.
* Ответ на неизвестный/устаревший `prompt_id` не приводит к ошибке: приходит
  `prompt_done{id, expired:true}` — приложение просто закрывает карточку.

### Кадр `prompt_done` (сервер → клиент)

```json
{"t":"prompt_done","id":"5f6a…","option_id":"once"}
```

```json
{"t":"prompt_done","id":"5f6a…","expired":true}
```

* `option_id` — фактически применённый вариант (может отличаться от присланного, если сервер
  заменил недопустимое значение на безопасное).
* `expired: true` — карточка закрыта по таймауту или была уже неизвестна.

## Медиа в обе стороны

Один кадр `media` переносит один файл. Крупные файлы отправляются несколькими кадрами и
собираются на принимающей стороне.

### Медиа от приложения агенту (клиент → сервер)

```json
{"t":"media","id":"m1","kind":"image","mime":"image/jpeg","filename":"photo.jpg","caption":"Смотри","data":"<base64>","part":0,"parts":1}
```

* `kind` — `image`, `video`, `document` или `audio`.
* `mime` — MIME-тип; если не задан, сервер определит по `filename`.
* `filename` — имя файла (необязательно, но важно для документов).
* `caption` — подпись (необязательно); для `audio` работает как распознанный текст.
* `data` — содержимое куска в base64.
* `part` (с 0) и `parts` (всего кусков) — для файлов больше одного куска.
  Файл ≤ 8 МБ уходит одним кадром (`parts: 1`); крупнее — кусками по ~3 МБ
  (`part: 0,1,2…`). Адаптер **собирает все куски** и только потом отдаёт файл агенту,
  поэтому обрывать серию нельзя — досылайте все `part` до `parts-1`.

### Медиа от агента приложению (сервер → клиент)

```json
{"t":"media","id":"a1","kind":"image","mime":"image/png","filename":"chart.png","caption":"График","part":0,"parts":1,"final":true,"size":20480,"data":"<base64>","reply_to":null}
```

* `kind` — `image`, `voice`, `video`, `document` или `animation`.
* `part`/`parts` — как выше; `final: true` — последний кусок файла.
* `size` — полный размер файла в байтах (не куска).
* `data` — кусок в base64 (может отсутствовать, если файл отдаётся ссылкой).
* `url` — альтернатива: ссылка на файл (приложение качает само), если файла на диске нет.
* `reply_to` — `id` сообщения, на которое отвечает медиа (если есть).
* `caption` — подпись.

### Лимиты

| Предел | Значение |
|---|---|
| один медиафайл (в обе стороны) | 8 МБ (`max_media_bytes`) |
| размер куска при передаче больших файлов | ~3 МБ |
| один кадр WebSocket | 16 МБ |
| текст сообщения | 12 000 символов |
| аудио (`audio`-кадр записи голоса) | 8 МБ |

Если входящий файл больше 8 МБ или превышен размер кадра — сервер отвечает `error`
с кодом `too_big`; разбивайте файл на куски (`part`/`parts`) или сожмите его.

## Стриминг и индикатор «печатает»

При включённом на стороне агента стриминге ответ приходит не целиком, а по мере генерации:

1. Первое `message` с новым `id` показывает текст.
2. Последующие `message` с **тем же `id`** и полем `edit: true` — это **правка** того же
   сообщения: приложение перерисовывает его, а не создаёт новое. Поля `chunk` в таких кадрах
   служат только для нарезки по длине (`{index:0,total:1}`), а `final: true` в последней
   правке означает конец.
3. Если `edit_message` не удался, шлюз не теряет текст — дошлёт хвост обычным `message`.
   Обработка `edit:true` необязательна: клиент может игнорировать это поле и показывать
   каждый кадр как новое сообщение (но тогда видны дубли — лучше перерисовывать по `id`).

```json
{"t":"message","id":"r1","text":"Идёт","edit":true,"chunk":{"index":0,"total":1},"final":false}
{"t":"message","id":"r1","text":"Идёт ответ…","edit":true,"chunk":{"index":0,"total":1},"final":true}
```

Индикатор «агент печатает» включается кадром `typing` (обычно вместе с `avatar:thinking`) и
гасится кадром `typing` с `stop: true`:

```json
{"t":"typing"}
{"t":"typing","stop":true}
```

`stop: true` — это явный сигнал выключить индикатор сразу, не дожидаясь таймаута аватара.

## Коды ошибок

| Код | Когда | Что делать приложению |
|---|---|---|
| `auth_required` | кадр пришёл до `hello` | отправить `hello` |
| `auth_failed` | неверный токен или устройство вне белого списка | показать «нет доступа», не повторять |
| `bad_frame` | не JSON/нет обязательного поля | исправить кадр; фатальные — переподключиться |
| `unsupported_frame` | неизвестный тип или неподдерживаемый формат/тип медиа | обновить приложение |
| `too_big` | превышен предел кадра/текста/аудио/медиафайла | разбить сообщение, слать файл кусками или сократить |
| `device_offline` | доставка на устройство, которого нет в сети | повторить позже |
| `internal_error` | внутренняя ошибка адаптера | показать общий текст, переподключиться |

## Голос

Приложение записывает WAV (16 кГц, моно) и отправляет base64 в кадре `audio`. Адаптер
сохраняет файл на диск шлюза и передаёт агенту как `MessageType.VOICE` с путём к файлу —
дальше работает штатное распознавание речи Hermes. Если в приложении есть собственное
распознавание (или текст набирается руками), поле `text` заполняется — тогда агент получает
и текст, и аудио. Голосовое от агента приходит кадром `media` с `kind: "voice"`.

## Адресация устройств

Доставка в мобильное приложение (cron, `hermes send`, `deliver`) адресуется по устройству:

* `mobile:<device.id>` — полная форма (`hermes send --to mobile:tel-1`);
* `<device.id>` — краткая форма (`hermes send --to tel-1`): адаптер сам подставит префикс.

`session` в кадре `ready` — это тот же адрес (`mobile:<device.id>`). Устройство по умолчанию
для cron задаётся переменной `MOBILE_HOME_DEVICE` на машине агента.

## Версионирование

Обратно совместимые дополнения — только новые **необязательные** поля и новые типы кадров
(клиент их игнорирует). Несовместимые изменения — версия `v` в `ready` и в документации.
Карточки-вопросы, медиа, правки `message` и `typing.stop` — обратно совместимые дополнения,
поэтому версия остаётся `1`.
